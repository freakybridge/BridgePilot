# bridgepilot-git-sync

由当前控制对话编排，复用各项目实际安装的 [git-sync](../git-sync/SKILL.md)。显式调用授权本轮所选项目的对应模式；咨询、查看名单或修改技能本身不授权同步或发布。

## 模式

| 调用 | 行为 |
|---|---|
| `$bridgepilot-git-sync` | 全部已登记下游项目普通同步 |
| `$bridgepilot-git-sync release` | 全部已登记下游项目正式发布 |
| `$bridgepilot-git-sync [release] --project <精确项目 ID 或名称>` | 仅处理指定项目；多个项目重复传 `--project` |

先解析模式，再解析项目范围。`release` 是模式参数，不作为项目选择器传给名单脚本；未知参数或无法解析的范围停止，不回退为全量或普通同步。未指定 release 时保留普通同步行为，不能自动发布。批量 release 授权覆盖所选项目各自原生发布流程中的必要构建、提交推送及正式发布，不延伸到部署、用户环境安装或清理。

## 定位与范围

读取相邻 [bridgepilot](../bridgepilot/SKILL.md) 的本机绑定，按其流程核验实际 home、skill-status、bp-git-sync-skill-v1 和 bp-sqlite-status-v1，再调用只读 status。不能将当前目录或发行包猜作私有 workspace。本技能及名单脚本由 BP 打包、安装和校验；skill-status 须报告本入口 current=true。安装本入口不授权执行同步或发布。

用本技能 `scripts/list_projects.py` 读取绑定指向的 SQLite，默认列出全部登记项目；指定子集时重复传 `--project <精确项目 ID 或名称>`。示例（脚本路径以本技能实际目录为准）：

```text
python <本技能目录>/scripts/list_projects.py
python <本技能目录>/scripts/list_projects.py --project StratusAgent --project HoldemTrainer
```

脚本只读、无迁移，不访问原生聊天或凭据。缺库、旧 schema、未知或歧义名称均停止范围解析，不能降级为全量同步。项目名单和本机绑定来自数据库，不硬编码目录、仓库或机器 ID。未登记项目先报告缺口，不自动登记。

依据输出的暂停标记、custody、runs 和 operations 核对本机控制权及在途操作；暂停、交接冻结、活跃或 Unknown 执行只阻断相应项目，不抢占或自动恢复。不确定状态先沿 BP 入口核销；缺本机唯一绑定、缺目录或非本机 host 的项目标记未执行。数据库未登记其他编辑者，仍须核对当前会话已知的并行写入。

## 并行执行

派发前核对各绑定的真实 Git 根、仓库身份及实际推送目标，读取项目 AGENTS 和必要入口。登记路径发生漂移不猜替代目录。同仓库的重复绑定、符号链接及共享 Git common-dir 的 worktree 只允许一个执行者；含义不明先报告，不并行修改共享 Git 状态。

本次调用允许使用子 agent 分担独立项目的只读核对和审阅，每个执行者只负责一个仓库；受管 git-sync 命令由主对话执行。按当前可用并发槽位有界派发，超出容量排队；没有子 agent 能力时明确说明并顺序执行，不声称并行。使用当前模型和推理设置，不创建用户侧新聊天、heartbeat 或独立服务。

每个执行者接收：项目 ID、真实目录、仓库、所选范围、明确的普通／release 模式及对应授权、只读职责，以及失败时保留现场的要求。它必须读取自己的项目规则与实际 git-sync，不以主对话的摘要替代必要审阅；普通模式禁止 release。敏感内容、私有远端和精确发布范围等项目既有约束仍适用；实际缺授权时暂停该项目并汇报，其他项目继续。

普通模式沿 git-sync 的受管入口完成一次 preflight、真实 diff 审阅、中文提交消息、提交、推送及独立核验。不隐式升版或执行 release。没有差异时允许 no-op，仍按受管结果判断是否存在待推送提交。

release 模式由主对话对每个项目只调用一次其受管 `git-sync release --publication-required`（可附已有 `--message-file`），具体流程以该项目实际 git-sync 为准。CLI 内完成聚合预检、远端接入、必要原生产物准备、提交推送、正式发布及最终远端核验；外层不另跑 preflight、普通同步、打包或 gh 发布。工具缺失或不具备完整发布能力时阻断该项目，不能省略保护参数或降级普通同步。工作区干净不代表已经发布，不能因此跳过发布入口；无变化不重复升版，已有有效产物由 CLI 复用。

两种模式均不得手工拼 Git 写操作替代受管流程，不隐式安装工具、升级骨架，也不自动修复业务、补验收或开展无关测试。需要扩大范围或新增工作环节时只暂停相关项目。

任一项目失败或发布条件不满足时，保留工作区、冲突、stash、已生成提交及发布接续信息，继续其余独立项目。普通 push 失败不重跑整个同步、不重做提交、不强推；release 失败按 CLI 报告的已完成阶段、阻点和接续条件处理，不能整批盲重发。结果未知先查询核销；具备接续条件后仅对受影响项目再次调用同一 release 入口，不重复升版或覆盖既有版本。平台强制确认和真实敏感范围缺口交用户处理，不能由其他 agent 自称获准代替。

## 汇总

等待已派发工作结束并核对各项目真实收据；后续新增项目不自动加入当前批次。普通模式按项目汇总：提交摘要与 commit、推送成功／no-op／失败／未执行、实际推送目标、工作区与 stash、阻点。没有独立核验的结果明确标注未验证；模型 completed 不等于同步成功。

### release 版本报告

只有收据同时满足 `status=released` 和 `publication_verified=true` 才报告该项目发布完成；`synced`、源码已推送或本地产物就绪均不算发布完成。部分项目成功不能宣称全部成功。

比较口径固定为**上次正式发布 → 本次正式发布**，先整理证据，再输出以下两部分：

**主程序版本汇总**：每个选中项目一行，成功、失败、未执行和未验证项目均不得遗漏；旧、新版本必须分列，不能只给版本链接或箭头摘要。

| 项目 | 旧版本 | 新版本 | 发布结果 | 变化子包数 |
|---|---|---|---|---:|

**变化子包明细**：按项目分组、逐包列全相对正式基线的版本变化，不用“等若干包”省略；未变化子包不展开。各项目明细数须与主表已核实的变化数一致。

| 所属项目 | 子包 | 旧版本 | 新版本 |
|---|---|---|---|

全部项目的子包均确认未变时，在明细位置写“本轮所有项目均无子包版本变化”，不造占位子包。即使只有主版本变化，也保留主表旧、新版本并将变化子包数记为 0。

数据与例外规则：

- 优先复用本次 CLI 确认的正式基线（版本和 commit）、成功收据，以及与两端固定提交对应的原生发布说明／版本清单。必要时只补读这些提交的原生 manifest；不额外运行 release、构建或整套预检，不固定扫描全仓历史。
- 证据必须对应本次操作的 commit、tag 或指纹，不能把目录中遗留的 `source-input.json`／旧发布说明当作本轮基线。当前工作区版本、发布前 HEAD 和本轮自动编辑清单都不能替代正式基线；已提前升版但尚未正式发布的子包变化也必须纳入。
- `publication_reused=true` 且远端核验成功时，主表旧、新版本均填写该正式发布版本，结果写“复用已有发布”，变化子包数为 0；不得重放该 Release 首次发布时的旧升级明细。
- 缺少可靠旧基线时，旧版本写“未知（无可核验旧发布）”，不能默认为当前本地版本或零变化；只有证据明确证明首次发布时才写“—（首次发布）”。子包范围无法完整确定时，变化数写“未知”，可列出已确认明细，但必须说明不完整。
- 子包按项目原生身份匹配，目录移动不能直接判为新增。证据明确的新包／退役包分别在旧／新版本格标“—（新增）”／“—（退役）”；无法可靠匹配时标未知，不猜版本。
- 发布失败、未执行或未核验时，新版本栏写“未发布”或“未验证”，变化子包数不冒充已发布统计。已知候选版本及候选包变化放在失败说明中，明确标为候选，不混入成功发布的子包明细。

版本表之后保留简短发布凭证：各项目固定 commit、tag、Release 链接、资产核验结果和已有依据的变更原因；失败项目补充阻点、已完成阶段及继续条件。所有版本均未变化时明确说明未升版；没有依据的信息标未知，不补造成功结果。

本地结果摘要不是第二份 BP 任务档案。不为凑状态创建任务、Run 或 Released，不用普通同步核销现有开发任务，也不凭批量发布结果自动改写既有任务状态；已有 BP Run 的记录按其原有流程处理，不伪造收据。交付明确本轮模式，列出失败项目的具体继续条件。
