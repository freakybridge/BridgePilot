# bridgepilot-update

本 Skill 归 BP 安装器所有，不进入 Forge 共享分发。正常调用授权先确保本机 BP 安装为本次核实的官方版本，再升级所选下游骨架；默认不提交、推送或 release。咨询只解释；显式只读／dry-run 不获取源码、构建、安装或写收据，缺工具时报告预览缺口。

## 0. 先更新本机 BP

从已有本机绑定解析安装 home、Skills 根和私有 workspace，复用 [BP 安装入口](../bridgepilot/SKILL.md#无参数安装或更新) 的 `scripts/bridgepilot_update.ps1`。旧安装没有更新脚本时，从官方源码的 INSTALL 进行一次受管引导，不复制开发工作区文件冒充已发布来源。

必须取得 `BRIDGEPILOT_SOURCE_UPDATE_RECEIPT`，且 `status=source_update_completed`、程序安装和 Skill 核验成功；同来源、同安装身份复用有效结果，不强制重装。失败、pending 或未知结果时保留现场，停止下游写入。不能用仓库 VERSION、候选二进制或正式 Release 存在代替本机安装证明。

成功后读取实际已安装 home 下 `source/orchestrator/skills/bridgepilot-update/SKILL.md`，携带本次安装收据从下游阶段继续，不递归调用本节。只读模式跳过安装，使用现有合格工具；本节结果不授权恢复任务、接管、清理或业务环境安装。

由 BP 主对话编排整轮骨架升级，沿用 [BP 入口](../bridgepilot/SKILL.md) 的项目绑定、控制权和任务核验。实际维护、开发收口和发布分别使用当前可用的 bridgeforge-codex、develop、git-sync；能力缺失时报告具体缺口，不另造执行器。

读取本 Skill 目录的 `bridgepilot-local.json`，以实际 `home` 定位 `.build/bridgepilot/bin/bp.exe`；源码引导无绑定时按 BP 安装入口核对实际 home，不猜路径。正常调用的安装授权限于本节规定范围，不能扩展成发布授权。

## 1. 确定批次

复用当前对话、BP 已有任务和真实授权，确定项目集合、目标来源、阶段与发布范围。无项目参数默认全部已登记下游；显式指定时只处理该子集。用更新后的 BP `project-list --workspace <绑定工作区>` 获取名单；指定子集用该命令的内部 `--input`，内容为 `{"projects":["精确ID或名称"]}`，不维护第二份项目清单、不用外部脚本直接读库。暂停、控制权、在途／Unknown 操作及非本机绑定逐项目检查；独立项目受阻时保留并继续其余可维护项目，来源或本机 BP 全局失败则停止整个下游阶段。咨询只解释；只读 dry-run 不刷新产品、准备产物、接入远端或执行 apply。

开始就核对最后正式发布至当前的累计变化，以及暂存、未暂存、未跟踪业务改动。隔离未提交文件不能排除已提交的未发布业务；是否纳入须在长验证前明确。已有 release 授权仅在本轮项目、内容、目标仍匹配时继承，不成为以后批次的永久许可。暂停、恢复、预算及已确认决定跨阶段继承。

混合业务现场尽早确定获准基线与执行副本，保护原 HEAD、业务差异和 stash。优先复用合适工作区；需要隔离时沿可用的受管工作树流程，能力不支持时评估独立克隆，不重置原现场或擅自改发布分支。使用足够短的路径，临时数据放 `.runtime/tests/`，构建产物放 `.build/`。

## 2. 锁定来源与前置条件

在已有维护授权内，按 bridgeforge-codex 从官方入口刷新一次用户级产品，记录版本、不可变来源提交、实际 CLI 和 prepared 公共产物收据；同一批次复用，不逐项目重新追随上游。仅查本地版本不能称为最新。目标变化时更新批次决定，并核对受影响计划。

从各项目 INSTALL.md 及其明确导航进入，核对骨架身份、定制区、实际 Hook 调用、必要可执行文件、编码和验证环境。先核对低成本且可能阻断长任务的条件。缺安装说明、私有 Hook 或业务依赖时按归属处理，不把骨架维护扩成业务环境恢复；必要产物沿项目自己的锁定构建与安装入口准备。

项目发布入口由安装／升级阶段交付。已有原生声明保留；缺入口时按 bridgeforge-codex 更新规则形成一次项目所有的版本／构建／产物输入，纳入计划、驱动部署及就绪核验，不在 release 时补安装。批次共享公共 CLI/Hook 和驱动产物；各项目只补真正失效的输入，无差异不编译或写入。平台与实际 push 目标相符，GitLab 实例能力和 API 凭据有缺口时明确区分，不以公共 baseline 成功代替完整入口就绪。

检查需要本机回环、网络等能力时，确认执行环境；异常先做最小诊断，区分权限、环境和代码。不能把等待直接定为业务故障，也不禁用断言。

## 3. Dry-run 与问题决定

逐项目执行锁定来源的零写入骨架计划，保留原始收据与 fingerprint；显式只读模式仅在对话中返回，不写磁盘记录。骨架计划、发布范围预览、真实提交 Hook 各有覆盖边界；明确已检查与未执行部分，不用 dry-run 保证提交、推送或 runtime 成功。

单项目可用对话记录；跨项目或需要接续时维护一份批次记录。问题表至少包含：

| 编号 | 发现阶段 | 影响项目 | 根因与归属 | 处理方案 | 确认与执行状态 |
|---|---|---|---|---|---|

编号贯穿批次，不随阶段重编；合并问题保留关联及历史。相同报错不自动判为骨架共性缺陷，按根因区分通用产品问题、项目专项和环境问题。

需要改变骨架产品或项目行为的方案，先按 explain 说明事实、影响、取舍和验证，再复用已有决定。实质新范围或未决风险只暂停依赖动作并请求确认；已获准的常规参数纠正和环境重试不重问同一授权。一次性旧资产处理不自动变成永久兼容代码，不固化某次版本或项目名单。

## 4. 处理与升级

通用修复在 Forge 完成必要开发验证；需要官方发布、用户级刷新时须有对应授权，不从下游升级推导上游发布权限。项目专项留在项目，仅修改获准范围；源与生成镜像分开处理，保护资料、定制、业务改动和原生 Memory。

按真实内容、依赖、构建输入选择最小充分验证，优先暴露便宜的失败。复用仍有效的受管记录；确已失效才补对应检查和子包收口。不从包数或缺记录推定全包重测，不为放行删除输入归属、削减必需检查、猜造可复用环境或导入聊天 passed。

正式 apply 沿 bridgeforge-codex 的模式、保留决定和事务入口，复用仍有效的计划；最终指纹复核交给入口，不固定额外重跑完整 planner。漂移时核对真实变化，不只替换旧指纹。不写骨架戳，不手工复制公共资产或无差别归一化仓库。

失败保留实际命令、环境、标准输出/错误及恢复收据；输出不足时只重现失败项。版本、索引或安装中断沿受管恢复，不手改账本。环境重试不冒充源码修复成功，不重置预算和失败计数。

## 5. 按授权衔接发布

默认不 release。未获本轮明确且范围匹配的 release 授权时，完成安装后直接交付；已结束批次的发布授权不沿用。已有匹配授权时，主对话每项目只调用一次受管 `git-sync release`，由 CLI 完成聚合预检、原生准备、提交推送、平台发布和远端核验，不在外层追加预览、普通同步或手动发布，不再次索取同一授权。release 不补安装；真实入口缺口回到安装流程处理后接续。

批量发布遵守本轮统一就绪或分别发布的约定；仅在部分就绪确实改变结果而策略未定时补问。逐仓发布不具备跨仓原子性；沿已确认的批次策略保留成功结果，失败仅阻断相关项目，独立项目继续。提交成功但推送失败时保留提交，不强推、不盲重跑整套发布。

区分工具版本、主程序 VERSION 和独立子包版本。纯骨架 Git 差异可能保持业务版本不变；不制造空版本，不重复升级已收口子包，以当前工具的真实结果为准。

## 6. 核验与交付

逐项目展示安装收据的真实结论；需要时独立核对固定提交、实际 push URL 的远端 ref、工作区与 stash。分别说明升级、收口、提交、推送核验和 runtime 未验证项，不把模型 completed 当发布证明。

说明原执行现场是否已同步发布提交、业务差异是否保留；隔离副本发布不等于原脏工作区已快进。发布成功列主程序及全部累计变化子包的旧新版本与原因；业务版本未变则明确报告骨架 Git 交付。

已有 BP Run 时沿原生核验更新状态；工具不支持某种交付核验时保持实际状态并报告缺口，不能伪造 Run、收据或 Released。主对话维护不为凑状态创建聊天、调度或 heartbeat。证据与决定合并回唯一批次记录，不复制一套任务状态表。
