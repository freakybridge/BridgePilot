# git-sync

完整发布在 CLI 内先核对正式发布历史，由项目原生适配器按实际代码净差异决定是否升版，再固定源码并完成发布。有代码变化才准备必要的新版本；纯文档、验收记录和 TODO 更新不升版，不能仅按提交消息类型推断。无代码变化且当前版本尚未发布时完成该版本发布；已正式发布时同步本次源码增量并严格核验、复用原 Release，分别报告本次同步 commit 与原发布 commit，不移动旧标签或替换已发布资产。运行 Skill／模板等实际行为输入仍按项目原生规则计入代码影响。已有合理候选和失败重试不重复升版，关键分类不明才暂停，版本占用在提交推送前检查。不能靠删除接续记录解锁。

显式调用授权本轮指定范围。`git-sync release` 表示完成真实发布，不得缩减为源码提交推送。版本仍以项目原生文件为准；旧配置化 release、版本登记和收口账本保持退役。

1. 从项目 AGENTS 确定现有受管 CLI。工具缺失或未提供完整发布能力时报告缺口，不降级普通同步，不隐式安装或重建工具。
2. 普通模式沿原路径：一次 `git-sync --preflight`、审阅实际 diff、经 `git-sync --message-file <路径>` 提交推送。消息采用 `<类型>: <简体中文实际效果>`，正文写 `.runtime/` 文件，不经 shell 字符串中转。
3. **release 模式只调用一次 `git-sync release --publication-required`**（可附已有 `--message-file`）。用户仍只调用 `git-sync release`；附加标记让旧 CLI 在写入前拒绝，防止裸 release 被忽略，不新增检查命令。CLI 内完成聚合预检、远端接入、必要原生产物准备、提交推送、真实发布与最终远端核验。不要由 Agent 外层拆成预检、sync-remote、普通同步、打包、gh 发布等多次操作。有效产物复用，无变化不重复升版，不固定追加全量回归或人工草稿审批。
4. 只有收据 `status=released` 且 `publication_verified=true` 才报告发布完成，展示版本、固定 commit、tag、Release URL 和资产核验结果。`synced`、源码已推送或本地产物就绪均不是发布完成。子包累计版本变化及原因按项目原生发布说明报告。
5. 暂停仅限四类：关键决定缺失；不可自动处理的冲突；构建/校验/鉴权/权限/服务条件无法安全满足；需要新增工作环节、扩大范围或执行未授权操作。转述 CLI 的已完成阶段、阻断及接续信息；可安全恢复的短暂问题由 CLI 有界处理，结果不确定先查询，不能盲重发。再次调用同一入口接续，不重新升版或覆盖既有版本。新增环节须先取得用户确认。

不从当前调用推导其他项目部署、用户环境安装或清理授权。保留 stash、冲突与失败现场，不使用 --no-verify；不反复 self-test、外层核验或前置准备。输入或收据有实际矛盾时才补查，已有授权不重复询问。

首次连接有缺口时读[首次使用](references/first-use.md)，权限或运行异常时读[运行边界](references/runtime-context.md)；涉及旧发布参数时读[旧 schema4 退役边界](references/schema4.md)，不恢复该机制。
