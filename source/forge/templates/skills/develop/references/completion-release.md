# 原生版本与开发交付

Forge 的项目版本登记、develop 收口账本、自动稳定晋级及配置化 release 门禁已经退役，不再读取或重建 bridgeforge-version.json / package-closures.json。旧收据只能作历史资料，不用于证明当前候选。

1. 沿用当前任务范围与验证证据，读取项目 AGENTS / INSTALL 的原生构建、测试和版本规则。
2. 在已有授权范围内核对原生 manifest、根 VERSION、相关依赖和锁文件。版本判级遵守 SemVer；无变化或重复执行不升版。不凭包目录自动扩张任务范围。
3. 需要版本调整时使用项目实际支持的原生入口，先核对它的行为和影响，不猜造参数；未授权发布时不提交、推送或发布。
4. 核验最终构建产物、必要检查和原生版本一致。没有执行的运行环境或业务验收标为未验证。
5. 在当前唯一交付记录报告实际命令、结果、版本变化和限制。工程验证、用户验收与 Git 发布分别说明。

不调用已退役的 Forge develop、setup/migration/release 参数；不建立替代配置或账本，不将其搬到另一目录、改格式或塞入 hooks.json。普通 git-sync 保持可用，不主动升版。需要项目原生发布能力但入口缺失时说明具体缺口，只停止相关发布动作，不伪造 Forge 认证。
