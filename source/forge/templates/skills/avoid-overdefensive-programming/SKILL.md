# 清理过度防御

1. 从本次 diff 和已核对的调用链入手。只看新增、改动或因本次替换失去用途的防御分支。对照生产调用方、数据来源和兼容契约，区分真实可达状态、测试替身特例和内部已成立的不变量。
2. 仅清理能定位到具体依据的分支。内部调用已保证条件时，删掉重复判断。测试替身偏离生产契约时，修正替身。把异常或缺失映射成正常业务值的分支，按当前需求与契约恢复明确的错误或缺失状态。旧数据、外部失败、权限、并发、幂等和受支持的降级路径按真实契约保留。用途未明或涉及未授权的行为变更时，记录位置和待核实的依据。
3. 修改限于当前授权，审查请求保持只读。将相关路径并入 develop 的既有验证，覆盖被删分支的调用不变量和仍可触发的失败。结果只列实际清理、仍待确认的候选及验证依据。
