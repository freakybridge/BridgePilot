# 代码清理

默认处理本对话的改动。结合对话中的任务、相关提交、暂存与未暂存差异、相关新增文件定位到具体代码段。D3 沿用本次开发任务的范围；单独调用时优先采用用户指定的范围和类别。同一文件混有其他任务改动时只处理归属明确的部分。要求审查或预览时仅列候选和理由。

## 测试代码

删除清理范围内的所有测试代码，包括一次性测试、长期回归测试、集成测试和源码内联测试。默认范围覆盖本次新增、改写或因本次改动失效的测试。显式指定目录或仓库时，覆盖指定范围内的全部测试。

删除前核对调用方、测试注册和依赖。清理仅供所删测试使用的注册、夹具、依赖和辅助代码，包括放在生产模块里的测试专用接口。混合文件只删除范围内的测试部分。需要用待删测试取得验证证据时，删除前运行并记录结果。

## 过度防御性代码

对照生产调用链、数据来源和兼容契约，删除范围内所有已确认的过度防御性代码，包括调用方已保证的重复判断和不可达兜底。遇到把异常或缺失当作正常业务值的分支，按已确认的契约处理。保留外部失败、权限、旧数据、并发、幂等和受支持的降级路径所需的处理。

## 注释

删除过期或错误的注释，以及复述代码的繁琐注释。繁琐注释包含仍有效的原因、约束、单位或失败语义时，简写这些必要信息。涉及工具指令或公开 API 契约时，核对实际用途并修正过期或错误内容。

## 验证与交付

清理后核对差异、调用方、测试注册和依赖，按实际影响验证清理后的构建、调用路径和失败场景。从 D3 进入时并入 D4，注明哪些结果来自删除前运行的测试。说明实际清理、验证结果和仍有疑问的项目。
