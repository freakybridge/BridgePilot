# 代码清理

默认处理本对话的改动。结合对话中的任务、相关提交、暂存与未暂存差异、相关新增文件定位到具体代码段。D3 沿用本次开发任务的范围；单独调用时优先采用用户指定的范围和类别。同一文件混有其他任务改动时只处理归属明确的部分。要求审查或预览时仅列候选和理由。

## 临时测试

根据对话、交付记录和实际用途，清理已完成一次性诊断、复现或对比且无需再执行的测试，包括源码内联测试。保留固定功能契约、覆盖边界、防止缺陷复发或仍需用于验证和验收的测试。新增时间、文件名或未接入 CI 都不足以判定临时用途。

删除前核对调用方和测试注册，只连带清理该测试独占的注册、模拟数据和辅助代码。混合文件只删对应部分；共享依赖和用途未明的测试保留。

## 过度防御代码

对照生产调用链、数据来源和兼容契约，清理已由调用方保证的重复判断和不可达兜底。测试替身偏离生产契约时修正替身。遇到把异常或缺失当作正常业务值的分支，按已确认的契约处理。保留外部失败、权限、旧数据、并发、幂等和受支持的降级路径。

## 冗余注释

删除复述代码或描述已退役行为的注释。冗长注释中仍有价值的业务原因、约束、单位或失败语义应保留并简写。保留有工具或接口用途的注释，例如编译指令和公开 API 文档。

## 验证与交付

单独清理后核对差异和引用，按实际影响验证剩余测试、被简化的调用路径及仍可达的失败场景。从 D3 进入时并入 D4。说明实际清理、验证结果及有疑问而保留的项目。
