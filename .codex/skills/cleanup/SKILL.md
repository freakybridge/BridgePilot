# cleanup

显式调用即授权清理当前项目的约定范围，不逐项重复确认。`preview` 只读，不随后自动执行删除。只处理当前项目，不安装升级工具，不提交、推送或发布。

固定范围：完整保留 `.runtime/config/`、`.runtime/download/` 和 `.deps/`；清理其余运行产物。`.build/` 仅保留当前使用的程序、必需 DLL/资源和对应收据，其余清理。源码、Git、用户资料及三根以外内容不参与。当前运行必需的依赖若实际位于 `.runtime/`，须按原生配置明确保留，不因目录归类而破坏环境，也不在清理时搬迁。

1. 读取项目 AGENTS / INSTALL，核对真实 Git 根、当前构建/启动/发布入口及现有成品；Python 项目同时检查虚拟环境 `pyvenv.cfg` 的解释器位置。仅从当前原生配置和实际调用链确定完整保留清单，不照抄历史路径，不按时间猜当前版本。
2. 每个必需成品、资源目录、项目 Hook、运行依赖及收据使用精确项目相对路径；目录保留只用于需要完整保留的应用包或依赖，不泛化为整个 `.build`、工具目录或编译目录。来源不清时停止受影响清理并报告具体缺口。
3. 使用已具备 `explicit-cleanup-v1`、`junction-cleanup-v1` 和 `permission-skip-v1` 能力的当前项目受管工具；下游通常为 `.deps/bridgeforge/bin/bridgeforge.exe`，工厂为 `.build/bridgeforge/bin/bridgeforge-factory.exe`。调用 `cleanup --root <项目根> --products-reviewed --evidence <原生依据文件> --keep <精确保留路径>`；`--evidence`、`--keep` 可重复，保留项全部传入同次调用。原生依据可为 Cargo.toml、启动脚本、pyvenv.cfg 等，必须位于待清理的 `.runtime/`、`.build/` 之外。没有额外保留项时可省略 `--keep`，仍须核实产品并提供依据。预览追加 `--dry-run`。
4. 执行器自动保护其自身、原生发布驱动及收据；工厂入口另外保护工厂自己的精确工具和收据。项目其他当前成品仍须显式传入。工具缺失、版本不支持或非权限原因的 blocked 报告实际原因，不使用旧 JSON、shell 递归删除或外部临时清理器绕过。
5. 遇到已识别的目录 Junction：位于待删范围时仅删除链接本身，不进入、不统计或清理其目标；位于保留范围时保留链接。dry-run 单独列出链接路径、目标和 `remove_link_only`，实际删除前复核链接类型、身份和目标。项目根、产物根及扫描路径的祖先不得通过链接绕过边界；未知 reparse 类型、目录 symlink 和卷挂载点继续阻断。链接目标若独立位于其他已授权待删路径，按其自身路径处理，不通过链接扩张范围。
6. 遇到无权限访问或删除的条目，只读定位确切路径并记录原因，跳过该项，继续其余已授权范围；不逐项询问用户，不改 ACL 或所有权。现有工具因权限而阻断时，将已确认的权限条目临时追加到本次 `--keep` 后继续调用，保留原生依据与原有成品保护项；仅在权限跳过集合新增时重试，同一路径重复失败则停止重试并记入最终汇总。权限项须处于原定待删范围；项目根、产物根、配置、下载、依赖、当前成品及原生依据无法核实时仍阻断，不能列为手动删除项。路径越界、未知 reparse 类型、输入漂移等保护不能用权限跳过绕过。
7. 处理结尾一次性列出无权限条目的完整路径、原因及数量，提示“以下条目因权限不足未处理，请手动删除”。本次临时跳过清单不写入项目长期保留规则。实际清理有跳过项时整体报告 partial；dry-run 明确注明这些条目未纳入预览，即使底层对其余范围返回 completed / preview，也不能宣称全部清理或完整预览成功。
8. 报告 preview / completed / partial / blocked、保留范围、普通文件/目录与 Junction 各自待删或已删数量、失败路径。预览不创建目标项目内的文件、目录、锁或收据；不要将预览通过说成实际删除通过。执行继续使用既有 Windows 句柄、路径边界、实际占用与输入漂移保护，不杀进程、不改 ACL。
