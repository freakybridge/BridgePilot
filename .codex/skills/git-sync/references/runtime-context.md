# 同步权限与异常处理

仅实际权限、输入或失败恢复需要时读取。正常路径见根 Skill；不要求同一宿主进程，也不把本文件扩成第二套发布流程。

## 权限与有效分析

- 依据当前平台 .git 只读声明或明确本地文件拒绝确定执行权限，不试写探针、不改 ACL。网络、TLS、鉴权失败不是本地写权限证据。
- 为同一项目受管入口申请所需的最窄权限。在申请理由中引用用户本轮的实际调用或明确指令，列出仓库、模式、已核实的目标分支及该命令可能执行的写操作。普通模式区分按需提交推送与已确定的操作；发布模式写明标签和 Release 等实际发布动作。继承已有授权，不为各 Git 子命令分别申请。
- Codex 在命令启动前拒绝时，报告“平台拒绝启动”和原始理由，沿用已知仓库和已有授权。不要要求用户复述已知仓库名或发布意图，也不要换入口绕过拒绝。
- 工具身份由共用预检取得；日常同步不前置准备工具或独立 self-test。工具缺失、不匹配时报告维护缺口，不自动安装、改环境或回退手工 Git。
- 项目侧发布阻断限于五类。① 实际推送目标缺失、矛盾或不唯一。② 改动混杂且范围未定、Git 冲突、内容或目标漂移。③ 网络持续不可达、凭据或写权限不足。④ 原生命令、构建、版本或标签无法正确发布。⑤ 已有部分写入且无法确认远端状态。仅在确实需要用户决定时询问，恢复时沿用已有答案。
- 可安全快进就快进，再核对工作区。写入超时先查远端。GitHub 标签与固定提交相符时只补缺失的 Release；已有页面与预期一致时复用，结果矛盾时保留现场。报告失败阶段、固定提交、已确认的推送或发布结果。GitLab 按其原生发布收据核对。
- 普通同步的快进、暂存区保护、冲突和权限处理沿用普通同步入口。
