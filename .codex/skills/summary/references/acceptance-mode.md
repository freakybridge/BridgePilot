# summary accept — 验收差异

在共用 C1–C3 中加入下列内容，不重复执行普通总结。

- **C1：验收范围与已有证据。** 从当前交付记录和用户决定确定本次范围，对照必要完成条件及已有结果。已有明确验收不重复询问；必要证据缺失、冲突或 blocker 不标完成，已明确排除的场景保留未验证边界。
- **C2：正式验收记录与 TODO。** 优先补当前需求/设计/Bug 的验收段，写日期、用户决定、范围、实际依据、限制及相关完整 TODO 编号；符合合同才更新 lifecycle/validation_status。按[TODO 合同](../../todo/references/contract.md)与当前项目机器合同维护本次唯一相关条目，已读且未变的合同直接复用，不扫描结算无关事项。
- **C2：验收通过后的临时测试清理。** 仅在本次验收范围满足必要完成条件、用户确认通过且未要求只读时执行下述清理；证据缺失或 blocker 阻止验收通过时保留测试。
  - 范围限于本次已验收事项在 `scripts/tests/**` 和 `source/**` 中的相关测试，包括源码内联测试；不扫描清理无关功能。
  - 依据当前对话、交付记录和代码用途判断。明确标注为一次性诊断、复现或对比，且核对调用关系后确认无需持续维护的临时测试应删除；仅凭目录、文件名、本次新增或未接入 CI，不构成删除依据。
  - 固定功能契约、边界条件或防止已修复问题复发的长期回归测试保留，即使是本次新增。用途不明、同时承担回归职责或存在共享依赖的代码保留并报告，不推测删除。
  - 删除前核对调用方、测试注册和辅助文件；仅同步清理专属于被删临时测试的注册、引用及测试辅助文件。混有业务代码或长期测试的文件只删明确的临时测试部分，不改业务行为；影响无法界定时保留并报告。
- **C3：一致性。** 核对用户决定、文档状态、TODO 状态及验收链接一致；TODO 有变化时执行合同要求的只读检查。对测试清理做静态差异及引用检查，确认无悬空注册或引用、未误删业务代码和长期回归测试；在验收记录及回复中列出实际删除的路径/测试和判断依据，以及无法确定而保留的项目及原因，不列无关空状态。

仅明确发现的新独立问题按 TODO 合同去重记录，不主动寻找新问题，也不把原需求未完成项改称后续事项以绕过验收。已有条目缺少正式来源且本次获准记录决定时，按合同补最小决定记录；不为小事项补造完整需求卡。取消须保留实际用户决定和原因，不记成完成；旧 TODO 格式不自动迁移。

本模式仅做记录和清理所需的一致性检查，不补跑测试、构建或 smoke，不检查发布准备或自动 Git 同步；已有授权的事实记录不等于删除后重新验证通过，需要运行验证才能确定的影响如实保留并报告。
