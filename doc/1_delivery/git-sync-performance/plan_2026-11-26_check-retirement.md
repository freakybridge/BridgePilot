# git-sync 检查退役

2026-11-25 确认 A，次日实施。开发基准为 `29f305f`。目标为手写生产源码净删至少 1,000 行，分发镜像、清单、测试分别计数。实施预算为 2 小时、预计 4 万新增 token、主对话执行、最多两轮本地验收。

| 范围 | 最终行为 |
|---|---|
| Git 提交 | Forge 退役公共 pre-commit、工厂附加检查和会话启动时的自动注册。旧受管脚本随受管升级列入退役计划，按原字节备份。非 Forge 的独立 Hook 归项目所有。 |
| 版本和构建 | 发布直接使用原生版本与发布说明。项目构建和打包命令失败时返回错误；原生发布包仍可包含清单和校验文件。 |
| R1 | 读取项目入口、当前分支与推送目标，确认 Git 状态允许发布，取得发布锁。 |
| R9 | 核对提交内容，将固定提交推送至解析出的目标分支，并向远端 Git 核对提交号。 |
| 发布写操作 | GitHub、GitLab 创建固定标签、Release、附件；写操作发生错误或超时则停止并报告阶段。成功收据记录 `source_push_verified=true`、`publication_verified=false`。 |

退役范围包括旧发布记录接续、远端分支预整合、自动判版、版本占用预查、源码和产物的重复比对、release 内的提交类型及模板全检，以及发布后的远端内容复核。普通同步仍通过原入口运行。真实下游安装与对外发布由用户另行授权。

验收覆盖旧记录存在、版本固定、推送被远端拒绝、发布写入失败、零发布后读取，以及隔离项目升级及自有 Hook 归属。

## 实施记录

用户确认维持原两小时时间上限完成既定验收。首轮实际二进制在 GitHub、GitLab 本地替身上各通过 6 个场景。受管脚本完整备份、独立自有 Hook 保留、全新安装无 Hook 三组升级／安装样例通过，均重复核对计划无待写入项。BP 原生打包读取版本 `4.0.0`，生成标签名 `bp-v4.0.0` 和 16 项本地附件。隔离验证材料位于 `.runtime/tests/git-sync-retire-v22/`。

最终候选为 BP 4.0.0／Forge 22.0.0。本机三个受管工具构建并自检通过，`build-assets --factory --project-root . --check`、`manifest --root . --check`、`template-standard --root . --check`、`check factory-version --root .` 均通过；workspace 全目标锁定离线编译通过。最终两平台各 7 个样例按预期返回：固定版本成功、版本已占用、上传失败、推送提交号不符、非快进推送被拒、未完成合并，以及显式预检识别未完成合并。收据区分源码推送与平台写操作，模拟服务没有收到独立的发布内容查询。三组安装／升级均通过，包含原生打包和重复计划。综合收据为 `.runtime/tests/git-sync-retire-v22/verification.json`。

退役交付时，相对 `29f305f` 的手写生产代码净删 2,800 行。随后清理 GitLab 发布路径，复用入口已校验的主机与项目，删除已回滚方案的 9 个临时脚本和 3 个专用测试替身文件。清理后累计净删 **2,829 行生产代码**，源码内测试另净删 **410 行**。计数仅含 `source/` 的手写 Rust 实现和公共 Hook 入口。离线复测通过 GitHub 7 项、GitLab 8 项及 3 类安装／升级；新增用例确认凭据主机不匹配时不会向 GitLab 发送写请求。清理前收据另存为 `verification-before-code-cleanup.json`。真实平台及下游未发布或升级。
