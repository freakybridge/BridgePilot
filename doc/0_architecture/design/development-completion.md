# 工厂原生开发交付

本合同约束工厂自身，复用通用 develop 的 D1–D5，不向下游模板下沉工厂专属检查。旧配置化 develop、项目版本登记、收口账本及其自动 release 门禁已经退役；不以缺少旧账本否定原生工程验证，也不伪造历史认证。

## 范围与传播

沿用已有需求、授权与预算，区分本次修改和已有业务差异。首次影响判断明确产品层／自身配置／元文档、通用／工厂专属、适用版本与 CHANGELOG、dogfood 传播；不反复扩大任务或要求全仓清零。

正式维护源在 `source/forge/`，公共内容在 templates。公共源码投影是构建与消费副本，不作为另一开发根。工厂维护自己的文档索引；通用入口镜像与基线共用同一工厂适用筛选和路径转换。

## 必要验证

- 按实际影响选择最小充分的原生 Cargo 检查、测试、公共入口验证及独立复核，复用覆盖最终输入的证据。未执行的环境或业务验收明确标为未验证。
- 受管 Rust workspace 为 Forge 九包及平行 BP 包；`.codex/hooks/` 仅为公共八包投影，不启用工厂测试 cfg。
- 独立测试和固定样本在 `scripts/tests/`，构建输出显式进入 `.build/`，测试日志及临时数据进入 `.runtime/tests/<任务>/`。不为测试放宽路径、回滚、外部修改保护或真实断言。
- 模板变化先执行工厂 `template-standard`，再生成 manifest／dogfood；`--check` 必须零写。工厂不得使用下游 adopt/apply。
- 公共工具变更经 `build-assets --factory` 准备，核对源、锁、配方、自检及回执；失败保留场景。已准备工具的 `--check` 不启动 Cargo、自检或创建缓存。
- 真实下游写入须有本次明确授权，先备份、dry-run 和漂移核验，再应用固定候选。私有 Hook、Skill、项目区、Git 状态、业务差异及当前成品分别核验；隔离通过不冒充实盘完成。

原生命令与输出目录见根 AGENTS／INSTALL。完整回归仅在项目规则或具体风险要求时执行，不固定重复冷构建或为凑收据增加测试。

## 版本与交付

三条产品版本分别为 BP（根 VERSION，从 1.0.0 起）、BF（source/forge/cli/Cargo.toml）及 orchestrator（source/orchestrator/cli/Cargo.toml）。内部 Rust 包保留原生版本；根 workspace 不继承统一产品版本。依赖锁、产物及安装包中的组件身份须一致。具体迁移、发布范围与验收见[三产品版本治理](../../1_delivery/plan_2026-11-03_three-product-versions.md)。版本判级遵守 SemVer，实际版本修改和发布遵守本次授权；本地候选不是正式发布。无变化或重复执行不升版。

普通受管 git-sync 只同步，不主动升版；原生发布、提交和推送分别核实授权。不调用已退役的 Forge release 参数，不恢复版本 JSON、旧账本或自动认证能力。必要交付记录汇入当前唯一主题，报告真实命令、结果、范围和限制；用户验收前不将需求卡 lifecycle 标为 completed。
